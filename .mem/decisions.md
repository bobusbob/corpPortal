# Decisions: Каркас корпоративного портала

## 1. Регистрация через Supabase Auth и profiles

**Date:** 2026-11-26

**Decision:** Почта и пароль живут в Supabase Auth. Таблица `public.profiles` хранит имя, имя пользователя, почту и даты. Строка профиля создаётся триггером при появлении пользователя.

**Rationale:** Пароль не нужно хранить и проверять самим. Auth уже делает хеширование, сессию и подтверждение почты. Профиль остаётся обычной таблицей портала.

**Alternatives:** Отдельная таблица users с паролем в открытом или самодельном виде. Отклонено: это хуже защиты и дублирует Auth.

---

## 2. Проверка имени до входа

**Date:** 2026-11-26

**Decision:** Функция `is_username_available` доступна роли anon и возвращает только boolean.

**Rationale:** Форма регистрации должна сказать, что имя занято, ещё до создания сессии. Читать саму таблицу profiles гость не может.

**Alternatives:** Не проверять имя заранее и полагаться на ошибку триггера. Оставили функцию, потому что сообщение на форме понятнее.

---

## 3. Подтверждение почты пока выключено

**Date:** 2026-11-26

**Decision:** В Supabase выключен Confirm email. Регистрация сразу создаёт сессию и открывает кабинет.

**Rationale:** Для проверки портала письмо мешает. Пароль по-прежнему хранит Auth.

**Alternatives:** Оставить подтверждение включённым. Вернём перед настоящей публикацией.

---

## 4. Роль администратора в profiles

**Date:** 2026-11-26

**Decision:** У профиля есть роль `user` или `admin`. Администратор читает, меняет и удаляет все профили. Обычный пользователь не может сам поставить себе роль `admin`.

**Rationale:** Полные права нужны отдельной учётке, а не ослаблению доступа для всех.

**Alternatives:** Отдельная таблица ролей. Для одного администратора хватает поля в профиле.

---

## 5. Вход по имени пользователя

**Date:** 2026-11-26

**Decision:** Форма входа принимает имя пользователя и пароль. Почта для Auth находится функцией `email_for_login`. Администратор меняет имя, почту и роль через `admin_update_profile`. Имя пользователя и дата регистрации этой функцией не принимаются.

**Rationale:** Supabase проверяет пароль только по почте или телефону. Имя пользователя остаётся логином портала, а почта не показывается на форме входа.

**Alternatives:** Хранить пароль отдельно от Auth. Отклонено: пароль остаётся в Auth.

---

## 6. Публикация через GitHub Actions

**Date:** 2026-11-26

**Decision:** Сайт собирается в `dist` и публикуется на GitHub Pages адресом `https://bobusbob.github.io/corpPortal/`. Публичный ключ Supabase берётся из `.env.production` на этапе сборки.

**Rationale:** GitHub Pages не выполняет Vite и TypeScript. Нужна готовая статика. Отдельный хостинг пока не нужен.

**Alternatives:** Выкладывать корень репозитория. Так браузер получает исходный `index.html` и пустую страницу.

---

## 7. HashRouter и относительный base

**Date:** 2026-11-26

**Decision:** Маршруты в hash, сборка с `base: './'`.

**Rationale:** Так статический сайт позже открывается с GitHub Pages без настройки серверных редиректов.
